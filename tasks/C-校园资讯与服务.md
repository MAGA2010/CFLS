# C 企业级任务书 Web 管理后台与内容运营

## 0. 角色与交付

你负责 Web 管理后台的可用性、内容编辑与审核流程、合成咨询查看、审计界面和后台测试；A 负责 API 的鉴权和实际数据写入，B 负责小程序。先读 README、[工程约定](../docs/共同约定.md)、[架构/API](../docs/系统架构与数据契约.md)、[安全运维](../docs/安全部署与运维.md) 和[测试验收](../docs/测试与验收用例.md)。默认 Vue 3 + TypeScript + Vite，实际以第 1 天团队约定为准。

阶段结果：可构建的 Web 后台连接真实测试 API，编辑、审核、发布和下架闭环能在不同角色下验证；招办只查看合成测试咨询；操作错误、权限、并发、空态和审计清晰。权限验证必须由服务端做，前端只负责正确展示、隐藏不可用操作和解释错误。

## C-01 工程、布局、认证和权限提示 P0

1. 在 `apps/admin` 构建应用：项目结构、环境配置、路由、统一请求封装、错误边界、测试和构建脚本；按 A 的包管理/锁文件约定协作。
2. 提供登录、注销、当前账号/角色与环境提示；页面刷新后通过 `/me` 判断会话，退出后清理界面敏感状态。禁止硬编码账号、密码和长期令牌。
3. 按实际认证方案携带会话并处理 CSRF，使用精确可信 API 地址；401 返回登录，403 展示无权限，429 提示稍后重试，500 显示 requestId 和安全信息，不泄露堆栈。
4. 提供主布局、侧栏、面包屑、列表筛选区、分页、表单字段、确认对话框、状态标签、空/错误/加载状态。以 1366px 和 1920px 桌面宽度为最低适配；表单有标签和错误提示，键盘可访问主要操作。
5. 根据 `/me` 的角色展示可用入口；对隐藏的动作仍按服务端返回处理，禁止以页面显示作为授权依据。仅允许 admin 看到审计入口，admissions/admin 可见测试咨询入口。

**验收：**登录成功/失败/会话过期/退出均有正确结果；401 和 403 区分；角色不同的用户看到相应入口，直接请求越权由 A 的 API 拒绝。

## C-02 内容模型和编辑 P0

1. 设计内容列表：按 type/category、状态、更新时间筛选；分页；标题、栏目、状态、作者、更新时间和操作可见。若 API 尚未支持某个筛选，不做伪功能，提出接口变更。
2. 支持新建和编辑草稿，字段至少包含 type、category、title、summary、body；数据源与 A 的字段和 25 项分类映射一致。区分必填/上限、非法值和服务端错误；空内容不可送审。
3. 安全正文优先纯文本或受控结构化段落；不得将不可信内容直接作为 HTML 执行。预览展示待发布标识，不提供绕过审核的公开链接。
4. 编辑时带 `version`。收到 409 时提示有人已修改，保留本地未提交输入，提供刷新/比较或人工复制方案；绝不静默覆盖他人内容。
5. 列表/编辑的空内容、慢请求、断网、服务端不可用和重复提交都有明确处理；保存成功以服务端响应为准，防重复点击。

**验收：**同一草稿从列表进入编辑并保存可重新打开；错误输入有对应字段提示；并发修改不覆盖；脚本输入不会在预览和列表执行。

## C-03 审核、发布、下架和可追溯 P0

1. 实现状态 `draft`、`pending_review`、`approved`、`published` 的中文标签和可执行动作；作者可送审、独立 reviewer/admin 审核或驳回、审核者发布/下架。
2. 驳回填写原因；自审或非法状态变更在服务端拒绝后，前端保持数据并显示可理解信息。提交动作携带 version，并处理 409 冲突。
3. 发布/下架需要确认当前对象和动作；发布成功后展示时间、状态及可追溯 ID；不伪造线上发布结果。
4. 显示该内容可获取的修订/审核信息；若 API 尚无历史明细字段，先提交契约需求并诚实标记缺口，不能编造历史。管理端审计列表应包含 actor、action、target、result、time、requestId 并支持分页。
5. 联动 B：编辑创建→送审→另一个审核账号审批→发布→小程序展示；下架后公开端不可见；每步记录证据。

**验收：**流程按不同账号完整走通；自审和强制跳状态被拒；驳回原因可查；发布后和下架后的公开显示符合契约；审计只允许 admin。

## C-04 测试咨询管理 P0

1. admissions/admin 可进入测试咨询列表和详情；明显标注“仅测试合成数据”，显示必要字段、类型、时间和处理状态。
2. 其他角色直接访问路径时显示 403，不缓存或显示已载入咨询内容；退出/切换账号时清理界面状态。
3. 支持分页和空态；不导出、不向邮件或企业微信发送、不接触真实咨询。若处理状态修改超出 v1 API，先与 A 确认并更新契约，不做伪按钮。
4. UI 不写完整表单数据到日志、错误监控或 URL 查询参数；截屏只使用虚构值。

**验收：**B 发送一条虚构咨询后 admissions 与 admin 可见；editor/reviewer 不能通过 API 或页面读取；切换账号无上一个账号的数据残留。

## C-05 内容录入与管理说明 P0/P1

1. 与 B 共建 25 项映射，列出栏目编号、后台 type/category、用户端入口、真实内容是否已确认、负责人；先录入明确标识的合成示例，不能将虚构成绩、收费或联系方式当官方信息。
2. 编写给学校内容编辑人员的操作说明：登录、栏目选择、草稿、预览、送审、查看驳回、审核、发布、下架、故障求助和账号权限。教程只使用合成截图。
3. 审计与操作记录、后台搜索筛选按契约实现；细粒度栏目权限、素材上传和导出为 P1，除非 A 已实现并联测通过，不得展示伪功能。
4. 写组件/状态测试、API mock 错误测试、关键业务流程端到端测试；复核 B 的页面和跨端映射。用两种桌面宽度测试表单、长文和表格滚动。

**验收：**非开发人员根据文档可以在测试环境完成草稿到发布流程；25 项映射与小程序和后台一致；审计记录与操作一致；测试和截图可复现。
