# C 任务书 学生会、校园活动、新闻与招生服务

## 你的结果

负责学生会与校园社团、新闻活动、招生入学、咨询及联系等用户旅程。具体对应申请书 15—21、24—25 项，另外覆盖学生会展示；与 B 对接校园生活入口，与 A 对接新闻数据和本地发布演示。所有表单为明确标注的本地模拟，严禁真实信息和真实发送。

先读 [共同约定](../docs/共同约定.md) 和 [验收表](../docs/七天排期和验收.md)。使用 A 定义的路由/数据服务；公共路由及全局配置交 A 合并。B 负责寄宿与设施内容，你负责校园生活统一入口和社团/学生会内容。

## 工作包 C1 学生会与校园活动

1. 学生会入口展示简介、组织结构、动态、通知和招新结构；暂缺内容明确显示待提供，不使用真实学生资料。
2. 第 21 项社团、体育、艺术：以明确虚构的至少 3 条示例展示名称、类别、简介和详情；有分类筛选或清晰分组。
3. 活动列表与活动详情：标题、类别、演示日期、简介、地点占位、报名入口；无活动、无效 id、活动结束等状态可读。
4. 活动报名只在内存中模拟，字段最少化，空值提示、成功反馈与重复提交控制；明确不发送、不存储、不得填写真实信息。刷新或离开后清空。
5. 校园生活入口链接到 B 的寄宿、餐饮、健康和设施模块；B 路径未就绪时先展示待完成占位，不复制两套真实数据。

**验收：**学生会和社团可从入口到详情并返回；三条活动或社团示例可区分；无效 id 不崩溃；模拟报名的验证、成功和清空状态可重复演示。

## 工作包 C2 新闻、活动与通知（24）

1. 使用 A 约定的 service 获取已发布内容；列表至少 3 条明确虚构的新闻/通知，展示标题、分类、日期和摘要。
2. 点击任一条按稳定 id 打开对应详情；无效 id 给出提示及返回。列表和详情不得分别写死造成不一致。
3. 提供新闻、活动、通知分类或关键词筛选（P1），无结果可清除；日期缺失、无图、正文长内容有合理显示。
4. 与 A 联调：草稿不出现在前台；发布后展示；重置后回到初始示例。若数据服务尚未完成，写适配层，最终替换为统一 service。
5. 不实现微信订阅消息推送，界面不得暗示用户已订阅或收到真实通知。

**验收：**任意两条列表和详情匹配；无效 id 有返回；分类/空状态正常；A 的演示后台发布一条后前台可见并能打开详情。

## 工作包 C3 招生入学（15—20）

1. 为什么选择我们：展示页面结构和待学校确认项，不自行编造学校优势。
2. 申请流程与时间线：以步骤组件展示示例流程，步骤、日期均标明演示并等待学校确认。
3. 入学要求与测试：提供内容区域和待提供说明，不编造年级、资格、测试及时间。
4. 学费与费用：仅显示“以学校正式公示为准/待确认”，不提供虚构金额或缴费链接。
5. FAQ：至少 3 条示例问答，内容只说明哪些信息待确认；可展开收起，展开内容能读到。
6. 招生咨询/预约：提供两个可辨识入口，允许共用同一模拟表单组件；字段和流程见下方。

**验收：**15—20 每项有路由或清晰可定位的区域；流程、要求、费用没有冒充真实政策的文字；FAQ 展开关闭正常。

## 工作包 C4 模拟咨询、预约与联系（20、25）

1. 咨询与预约使用虚构演示姓名、演示联系方式、咨询类别及可选演示留言；预约日期若提供，只是交互示意。不要要求学生姓名、身份证、家庭收入或其他敏感信息。
2. 表单顶部和提交按钮附近标注“仅供演示，不发送、不保存；请勿填写真实个人信息”。做必填、格式、长度和错误说明，错误提示关联对应字段。
3. 提交只在内存中完成；显示“模拟提交成功”，可清空或返回。禁用重复提交；刷新/离开后清空；不输出输入到日志，不请求网络、不持久化。
4. 联系页提供地址、电话、地图和客服的位置占位，内容待校方确认；无真实号码时不绑定电话，不创建错误的外链或客服入口。链接缺失时明确提示。
5. 日后真实服务的告知、字段、发送、保留、权限和处理流程由学校另行确定；不得把示例表单视为生产表单。

**验收：**空填、错误格式、正常示例、重复点击、离开再进入分别测试；控制台无输入值、无提交网络请求；联系缺失项不出现无效拨号和欺骗性链接。

## 内容映射与提交边界

为第 15—21、24—25 项以及学生会额外栏目填写映射：编号、名称、页面或锚点、负责人 C、演示/待确认状态、数据路径、验收操作和所需校方材料；按 A 提供位置提交或在 PR 提供片段。与 B 的 22—23 项和 A 的后台使用契约，不另建第二个全局数据源。
