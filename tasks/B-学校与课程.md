# B 任务书 学校、课程、升学与设施

## 你的结果

负责把校方资料中学校概况、课程体系、升学指导和校园设施转换成结构清晰、可浏览的页面和数据。具体栏目以申请书 25 项中的第 1—14、22—23 项为基础；和 C 共享校园生活入口。七天要求每项有页面或可辨识的待确认占位，不意味着捏造内容或完成生产数据库。

先读 [共同约定](../docs/共同约定.md) 和 [验收表](../docs/七天排期和验收.md)。开工先同 A 确认工程、路由、数据契约及目录；A 尚未提交时准备演示文案与数据结构，使用独立分支，不改公共配置。

## 工作包 B1 学校概况群（1—6）

逐项实现并维护内容状态：

1. 学校概况：简介、办学特色、图片缺失占位；名称须显示为待确认示例。
2. 校长致辞：标题、正文、人物照片位置及职务；没有授权内容时只显示待提供。
3. 使命、愿景、校训：分别呈现，不编写学校官方口号。
4. 发展历程：按年份排序的时间轴；虚构示例明显标注，不暗示真实历史。
5. 管理团队与师资：列表和可浏览详情或统一详情页；示例不使用真实人名和肖像。
6. 认证与合作：合作/认证项目展示区；无证据时显示待校方确认，不使用大学 logo。

**验收：**六项都有可发现入口、标题和内容或待确认提示；缺图、空列表和无效详情有明确提示；进入和返回无死路。

## 工作包 B2 学术课程（7—12）

1. 课程总览：9—12 年级学习路径示意；明确只是结构样例。
2. 9—10 年级基础、AP 和 A-Level：各有独立内容区或可直接定位的详情；包含课程简介、适用年级、科目占位与“待学校确认”。
3. 学科目录：至少 4 条虚构演示数据，可按名称检索或筛选；无结果显示空状态，清除条件后恢复。若搜索列为 P1，先保证完整列表和详情。
4. 校历：用无真实活动时间的示例展示列表；日期排序稳定，空日历可读。日历订阅作为后续，不要声称已接入微信日历。
5. 长列表、长标题和没有图片时，仍能返回及阅读。

**验收：**从课程总览可到各课程及学科目录；用示例关键词找到正确项目、无结果有提示；校历内容与示例数据一致，不冒充正式校历。

## 工作包 B3 升学指导与成果（13—14）

1. 升学指导体系：展示各年级规划的结构、指导服务和待确认内容。
2. 升学去向与学生成就：以明显虚构示例呈现年份、地区和项目；没有校方确认禁止使用真实学生、大学标识、录取率或排名。
3. 提供简单按年份/地区筛选或列表筛选（P1）；无结果可重置；如果无可核实数据，保留模块结构，不创建真实成果声称。

**验收：**入口可达、列表详情一致、筛选与空状态可操作，示例标签清晰；没有未经确认的升学数据。

## 工作包 B4 校园生活与设施（22—23）

1. 寄宿、餐饮与健康：分别提供文字和图片占位，缺失的学校信息标明待提供。
2. 校园设施：用分组列表展示教学、运动及公共空间的内容结构；图片缺失时提供替代信息。
3. 与 C 对接校园生活统一入口：B 交付本模块目标路径和展示组件或数据，C 负责入口整合；最终由 A 注册全局路由。

**验收：**校园生活入口可以到达 B 的内容；缺图片和无数据不空白；每项都可以返回上级。

## 25 项映射和内容规范

在 `docs/` 的共享映射文件中，为负责的 1—14、22—23 项填写：编号、中文栏目、页面或锚点、负责人 B、状态（演示内容/待校方确认）、数据路径、验收步骤和缺失资料。文件路径由 A 第一天确定；若共享文件有冲突，先在自己的 PR 提供片段交 A 汇总。所有页面数据通过 A 约定的 service 或模块数据读取，不把多份相同数据硬编码在不同页面。对图片、数字、日期、课程、招生与升学事实均不得虚构成学校正式信息。

## 验收与提交

- [ ] 负责的每个编号都有入口或明确占位，映射记录真实路径；示例与待确认状态可识别。
- [ ] 课程、升学和设施可从相应入口到达，返回路径正常；数据与详情一致。
- [ ] 使用至少两种屏幕宽度验证长文本、缺图、空列表和无效详情；留存截图。
- [ ] 搜索或筛选有结果、无结果与清除测试；未完成则列为 P1 遗留。
- [ ] 不提交真实姓名、未经许可的师生图片或自行编造的学校数据。
- [ ] PR 列出 16 项覆盖、改动路径、运行及实际测试结果、截图、已知问题、所需资料、对 A/C 的接口影响；由 C 或 A 评审。
