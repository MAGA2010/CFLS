# B 企业级任务书 微信小程序用户端

## 0. 角色与交付

你负责小程序的工程、用户体验、全部公开栏目和 API 接入，不负责修改后台鉴权或绕过服务端权限。先读 README、[工程约定](../docs/共同约定.md)、[架构/API](../docs/系统架构与数据契约.md)、[安全运维](../docs/安全部署与运维.md) 和[测试验收](../docs/测试与验收用例.md)。默认 uni-app + Vue 3 + TypeScript，实际以 A 第一天确认的工具链为准。

阶段结果：微信开发者工具中可运行的小程序，接入真实测试 API；学校 25 项内容均有清晰映射，核心内容和新闻读取已发布数据，测试咨询只提交合成数据；具备可复现测试、性能记录、适配记录和交接文档。小程序体验版或真机测试受账号条件影响，不能用 H5 测试代替。

## B-01 工程、组件、导航 P0

1. 在 `apps/miniapp` 初始化工程，确认构建工具、命令、输出、微信开发者工具导入和环境配置；提供开发者不需要私有路径即可重现的文档。
2. 和 A 确认包管理器、目录、OpenAPI/类型；封装 API 客户端，统一 base URL、超时、请求 ID、错误码映射，不写死生产地址或泄露后台凭据。
3. 建立页面路由/导航配置，包括首页、学校、学术、升学、校园、学生会、新闻列表/详情、招生、联系及测试咨询。处理 tab/普通页面跳转规则、返回栈、失效路径。
4. 建立统一组件：页面容器、标题、导航、内容卡片、图片占位、空状态、加载状态、错误/重试、按钮、表单字段、标记。统一字号、间距、颜色和可读对比度；可交互控件具有文本说明与可见反馈。
5. 标识当前为测试环境与合成示例。空白、网络失败、超时、未找到分别处理；不能无限 loading 或将失败显示成功。

**验收：**在微信开发者工具构建并打开首页和至少两个页面；网络断开时显示错误与重试；空数据不白屏；375/390px 下导航可操作。

## B-02 栏目映射与内容页面 P0

与 C、负责人共同维护 `docs/栏目映射.md`，字段至少为编号、栏目、用户端路径/锚点、后台 type/category、是否已发布、内容状态、资料提供人、缺口与验收。按学校申请书覆盖：

| 编号 | 栏目 | 用户端交付 |
| --- | --- | --- |
| 1—6 | 概况、致辞、使命愿景、历程、管理/师资、认证合作 | 按内容类型展示列表/详情或安全的单页区块；空缺明确提示 |
| 7—12 | 课程总览、基础、AP、A-Level、学科目录、校历 | 课程入口与详情；课程和校历无正式资料时占位；筛选/校历 P1 |
| 13—14 | 升学指导、去向与成就 | 结构化展示；未经校方确认不展示真实录取率和学生信息 |
| 15—20 | 为什么选择、申请流程、要求、费用、FAQ、测试咨询 | 信息由已发布内容驱动；费用待确认；咨询遵守 B-04 |
| 21—23 | 社团/体育/艺术、寄宿餐饮健康、校园设施 | 分类入口与列表/详情，未公开资料不伪造 |
| 24—25 | 新闻/活动/通知、联系我们 | 新闻列表详情和联系占位；活动高级功能 P1 |

学生会简介、动态、通知、招新是额外栏目，不应漏掉。前台列表和详情以服务端 `id` 一致关联；无需为每个编号都新造独立页面，但每项都必须有可达路径或锚点与可辨识的状态。正文按安全格式渲染，不执行脚本或任意 HTML。

**验收：**负责人照映射表逐项点击；缺失项提示、返回正确；页面只读已发布内容，无法通过猜 ID 浏览草稿；长标题、无图片及无内容可读。

## B-03 首页、内容与新闻 P0

1. 首页包含学校介绍、课程、升学、校园生活、学生会、最新新闻、招生入口；展示当前已发布内容或准确空态，不硬编码与详情冲突的内容。
2. 新闻列表至少展示三条合成已发布记录，包含标题、摘要、分类和日期；分页、加载中/失败/空态清楚；详情按 id 查询，404 提示并能返回。
3. 时间按约定展示并合理处理缺失值；图片不存在时使用授权占位，不将没有权限的学生照片或校徽打包进公开仓库。
4. 搜索/分类和校历为 P1；完成时说明边界、无结果、清除筛选和延迟/失败处理。未实现不放伪造的可点击功能。

**验收：**从首页打开新闻 A/B 分别验证标题与正文匹配；下架后刷新列表和详情不再可见；断网可恢复；长文本/大字体不会遮挡按钮。

## B-04 测试咨询流程 P0

1. 页面以醒目方式声明测试环境仅可输入虚构数据，不是正式报名渠道；生产版默认隐藏/禁用该入口，不接受真实信息。
2. 输入类型、字段长度、必填、错误提示与服务端契约一致；仅收最小合成示例字段。客户端验证用于体验，不能替代服务端验证。
3. 用户提交时为一次操作生成随机 `Idempotency-Key`，同一请求失败重试沿用该 key；数据改变应创建新 key。提交中禁用重复点击，网络异常保持输入并明确可重试，不展示假成功。
4. 成功后显示明确的测试成功状态；记录的仅服务端返回的非敏感结果。不在控制台、埋点或客户端持久化中存储表单正文；离开页面时按约定清除。
5. 联系页无已确认号码/地址时显示待确认并禁用拨号/导航；不使用虚假的线上客服、预约或费用信息。

**验收：**空填/格式错误/超长/正常合成输入/快速双击/网络断开/重试分别记录；后端同 key 最多一条记录；生产配置下入口不可使用；客户端日志无输入值。

## B-05 质量、性能与交付 P0

1. 为 API 客户端、关键数据转换、表单验证和重试行为写有意义测试；结合微信开发者工具进行路由、加载和真实触摸操作测试，测试报告写设备和版本。
2. 以 375px 和 390px 宽度检查首页、新闻、表单、长文本；至少记录横向溢出、遮挡、图片缺失、系统字体变化、返回栈。真机如可用补充；不可用明确记录。
3. 减小包体，避免无目的的大图和重复资源；记录包大小、首页数据请求次数和测试环境下加载时间、方法与限制。不得虚构生产性能。
4. 完成栏目映射、操作截图、视频片段、构建/导入步骤、环境切换、错误排查和遗留列表；第 7 天在最终 commit 回归。
