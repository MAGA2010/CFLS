# A 企业级任务书 后端、数据、安全和平台

## 0. 角色与目标

你对 API、数据库、认证/权限、审核工作流、安全基线、工程集成和交付运维负最终责任；B 实现小程序，C 实现 Web 管理端。你不负责替两端写页面，但须第一天给出可以并行的接口与示例，避免阻塞。先读 README、[工程约定](../docs/共同约定.md)、[架构/API](../docs/系统架构与数据契约.md)、[安全运维](../docs/安全部署与运维.md)、[验收用例](../docs/测试与验收用例.md)。如当前工程与文档不一致，先报告并由负责人决定，不擅自删除已有代码。

**阶段结果：**三端可运行并连接测试数据库；账号角色与服务端授权、内容生命周期、审计、测试咨询、迁移、自动检查、测试环境部署和恢复都有实际证据。不能把功能未验证的接口描述成可用。

## A-01 单仓库与可复现环境 P0

**实施：**

1. 第一天创建 `apps/api`、`apps/miniapp`、`apps/admin`、`packages/contracts`、`infra`，确定 Node/包管理器/框架版本及锁文件；与 B/C 约定各自目录和公共配置写入人。
2. API 工程提供统一启动、格式、lint、类型检查、测试、构建命令；编写 local 配置例子、`.gitignore`、README。避免将个人路径和真实密钥写进仓库。
3. Compose 配置 Postgres 与 API 的最小环境，数据库端口仅绑定本机或受控网络；加健康检查和受控依赖启动；API 不以 root 运行。
4. 提供显式的 migrate 和 local/staging seed 命令。种子含 4 类角色的合成账号和各栏目演示文章；不要在源码、日志或公开 issue 放可用账号密码。测试账号由开发者本地通过脚本生成，生产禁用。
5. 错误、环境配置校验、requestId、结构化日志和 liveness/readiness 基础设施可用；配置缺失时启动失败且错误不暴露秘密。

**验收：**B、C 在干净环境按文档从克隆运行服务、迁移、种子和 health；删空临时测试数据库后能重复搭建；PR 提供实际命令、环境和结果。

## A-02 数据模型、迁移和内容服务 P0

1. 按数据契约创建 users、user_roles、sessions、contents、content_revisions、audit_events、inquiries、idempotency_keys；字段、主外键、枚举、索引、时间戳和唯一约束采用 migration 管理。列出每个约束及其理由。
2. 内容类型和分类覆盖 25 项映射；对 title、summary、body 等白名单校验和长度限制。公开列表/详情只输出允许字段、只读 published；分页上限和稳定排序遵循契约。
3. 后台支持草稿创建、列表、详情、更新；作者与权限由服务端确定。通过 version 实施乐观锁，同版本并发修改只有一个成功，失败返回 409。
4. 草稿提交、审核、驳回、发布、下架按状态机和权限矩阵执行，校验 reviewer 不是提交者；拒绝非法跳转。内容变更、修订和审计放在同一事务中；事务失败不得残留半成品。
5. 基于无 HTML 的纯文本或经过严格白名单清洗的结构化内容，保证管理端输入不会变成可执行脚本；用 malicious 输入测试。

**验收：**自动化覆盖空列表、分页、无效参数/id、版本冲突、全部合法/非法状态及发布后公开可见/下架后不可见；数据库迁移在空库和已有数据上通过；公开 API 对草稿返回 404。

## A-03 认证、会话、授权和审计 P0

1. 实现登录、当前用户、注销；使用成熟库和服务端会话，密码慢哈希、随机会话标识、过期、撤销；HTTPS 环境下安全 cookie 属性和 CSRF 防护符合安全文档。本机例外只限 local。
2. 中间件验证会话，服务端逐动作验证 editor、reviewer、admissions、admin 权限及内容归属；多角色也禁止自审。禁用账户、过期或撤销会话均不可继续调用。
3. 登录限流和普通接口限流，明确存储、实例范围和测试方法；统一认证失败信息。日志避免密码、cookie、token、咨询正文和联系方式。
4. 审计登录成功/失败、授权拒绝、内容创建/修改/送审/审核/发布/下架，提供仅 admin 可读的分页接口；审计 actor 由会话确定，不接受客户端冒充。
5. 发布 OpenAPI：全部成功/失败码、认证方式、字段约束、分页及 request/response 示例；B/C 最晚第二天可调用。接口变更附兼容说明。

**验收：**以四种角色加匿名直接调用全部敏感端点；未经授权不能读/写/审计；editor 无法发布，admissions 不能看草稿，reviewer 不能审核自己的提交；注销后失效；审计和接口权限用自动化和手测各留证据。

## A-04 测试咨询端到端 P0

1. 仅 local/staging 明确开启 `/v1/public/test-inquiries`，生产无论客户端参数如何始终不可用；接收规定测试字段和 `isTest` 标识，长度及类型验证，不允许当作正式招生收集接口。
2. 实现 `Idempotency-Key` 的持久化、请求哈希比对、并发唯一约束及过期策略：相同请求重试不产生两条；同 key 不同内容返回 409；失败时不能虚报成功。所有数据为合成数据。
3. 招办和管理员提供分页与详情 API；其他角色和匿名拒绝，日志/审计不输出表单正文。给 B/C 提供合成数据请求、状态码、超时重试和清理方法。

**验收：**模拟两次并发同 key、相同 key 不同内容、无效字段、非测试环境、越权读取；实际数据库记录数与响应符合契约。

## A-05 CI、部署、恢复和接口联调 P0

1. 配置 CI：依赖安装、lint、类型检查、API 单元/集成测试、临时 Postgres 迁移、API/admin/miniapp 构建；不跳过失败任务。若微信开发者工具不可在 CI 使用，写清楚单独手测结果。
2. 准备测试环境部署配置、镜像版本、健康检查、日志脱敏、反向代理及 HTTPS 示例；禁止将数据库公开。写部署和回滚演练步骤，实施一次并记录。
3. 对合成数据做备份，并恢复到独立临时库，核对 schema、数量和状态；记录耗时、文件权限、命令和结果。生产备份策略不等于本次演练结果。
4. 同 B/C 第三天完成“创建草稿→送审→审核→发布→小程序展示”；第四天完成虚构咨询→招办查看；第五天组织集成和缺陷清理。
5. 第六/七天在固定提交运行验证，提交脚本、环境变量清单、数据字典、部署/回滚/备份文档、日志和指标说明、缺陷及后续上线门槛。

**验收：**CI 和部署日志有实际结果，restore 在独立库通过，核心链路可重现，健康探针数据库断连状态正确。无法验证的设备/环境明确标注阻塞。
