# 系统架构、数据模型和 API 契约 v2

> **v2 变更（2026-11）**：收编错误码注册表（6.1）与参考 DDL（4.1）；状态机补充失败码；幂等补充重放响应头。接口路径、字段与 v1 兼容；`CSRF_INVALID` 为新增错误码。本文件是三端唯一契约事实源，tasks/ 各任务书中的同名内容为同步副本，冲突时以本文件为准。

## 1. 交付架构和责任

```text
微信小程序 B ── HTTPS /v1/public ──┐
                                 ├── API 单体 A ── PostgreSQL
Web 管理后台 C ─ HTTPS /v1/admin ──┘       ├── 内容/审核/审计
                                        ├── 账号会话/RBAC
                                        └── 测试咨询（默认仅测试环境）
```

HTTPS 是测试/生产环境目标；本机开发可以 HTTP，禁止含真实个人数据。API 不依赖管理后台信任，所有认证、授权、校验、状态转换和审计在服务端完成。小程序和后台不得直接访问数据库。A 在第 1 天提交 OpenAPI 及可运行 mock/example；B/C 可以通过该契约和 mock 开工，第 3 天前切换到真实测试 API。路径、字段若需要改变，先改契约、写迁移影响并通知其他两人。

## 2. 项目结构和环境

```text
apps/miniapp/        B：uni-app/Vue 3 小程序
apps/admin/          C：Vue 3 管理后台
apps/api/            A：API、认证、业务、迁移
packages/contracts/  A 主责：OpenAPI、示例和生成/共享类型
infra/                A：Compose、部署配置示例
docs/                 全员：运行、映射、验收、运维
```

本地、测试、生产分离数据库、域名、密钥和账号；每次启动显示环境。`.env.example` 只放无效占位；local/staging 初始化合成账号和内容要显式命令，生产配置严禁初始化测试用户/数据。API 监听地址、CORS 和 allowed hosts 精确配置，不能默认以 `*` 凭证跨域。

## 3. 角色和数据权限

先交付角色级权限 P0，逐栏目权限 P1：

| 动作 | 匿名 | 编辑 editor | 审核 reviewer | 招办 admissions | 管理员 admin |
| --- | --- | --- | --- | --- | --- |
| 读取已发布内容 | 是 | 是 | 是 | 是 | 是 |
| 列表/读取草稿 | 否 | 是 | 是 | 否 | 是 |
| 创建/编辑自己的草稿 | 否 | 是 | 否 | 否 | 是 |
| 送审自己的草稿 | 否 | 是 | 否 | 否 | 是 |
| 审核/驳回他人送审稿 | 否 | 否 | 是 | 否 | 是 |
| 发布审核通过稿/下架 | 否 | 否 | 是 | 否 | 是 |
| 查看测试咨询 | 否 | 否 | 否 | 是 | 是 |
| 查看审计记录 | 否 | 否 | 否 | 否 | 是 |
| 创建/停用账号 | 否 | 否 | 否 | 否 | 是，P1 可用脚本管理 |

`admin` 可以审核其他人的内容，但不得审核自己送审的内容；同一账号持有多个角色也不得自审。所有权限服务端验证，资源归属和状态逐条检查。已停用、会话过期或已注销的身份不应访问受保护 API。非法 id 不得泄露无权限对象的内容；文档注明 403/404 采用策略并保持一致。测试账户不得用于生产。

## 4. 数据模型（最小字段与约束）

所有 id 使用不可猜测 UUID；时间以 UTC ISO 8601 保存和传输，展示按配置时区。迁移可重跑、种子只运行于 local/test，空库和有数据升级都要测试。数据库约束、服务端校验和事务共同维护一致性。

| 表 | 最小字段 | 约束 |
| --- | --- | --- |
| users | id、username、password_hash、status、created_at、updated_at | 用户名唯一，密码只保存慢哈希；停用后会话撤销 |
| user_roles | user_id、role | 联合唯一；角色只允许枚举 |
| sessions | id、user_id、token_hash/标识、expires_at、revoked_at | 随机不可预测、可撤销、过期检查；不存明文会话令牌 |
| contents | id、type、category、title、summary、body、status、version、author_id、reviewer_id、published_at、created_at、updated_at、is_demo | type/category 白名单，title 必填；version 整数乐观锁；只返回 published |
| content_revisions | id、content_id、version、snapshot、actor_id、created_at | 内容变更前后可追溯，不能靠前端提供 actor |
| audit_events | id、actor_id、action、target_type、target_id、request_id、result、created_at | 追加记录；不写密码、令牌、咨询正文或联系方式 |
| inquiries | id、kind、test_name、test_contact、message、status、created_at、is_test | 仅测试环境用合成数据；有白名单长度约束；测试数据不用于生产 |
| idempotency_keys | scope、key、request_hash、result_ref、expires_at | 作用域+键唯一；不同请求同键返回冲突；有效期可配置 |

`contents.type` 可用 `school`、`academics`、`outcomes`、`campus`、`student_union`、`news`、`admissions`、`contact`；category 细分 25 项并记录映射。内容原始编辑数据不得作为可执行 HTML 渲染：优先安全文本/受控结构化段落，若用富文本必须有服务端白名单清洗与输出安全策略。

### 4.1 参考 DDL（执行级，与 tasks/A 第 3 节同步维护）

> 迁移文件是实现事实源；本节定义不可妥协的结构约束。实现框架自选（NestJS+node-pg-migrate 等），但下列约束必须等价落地并在迁移 PR 中逐条写理由。

```sql
CREATE EXTENSION IF NOT EXISTS citext;

CREATE TABLE users (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  username      citext NOT NULL UNIQUE,
  password_hash text    NOT NULL,                      -- Argon2id；禁止明文/可逆加密
  status        text    NOT NULL DEFAULT 'active' CHECK (status IN ('active','disabled')),
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE user_roles (
  user_id  uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role     text NOT NULL CHECK (role IN ('editor','reviewer','admissions','admin')),
  PRIMARY KEY (user_id, role)                          -- 一人可多角色；自审禁令在服务端全量判断
);
CREATE INDEX idx_user_roles_role ON user_roles(role);

CREATE TABLE sessions (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id    uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash text NOT NULL UNIQUE,                     -- 只存 SHA-256(256-bit 随机 token)
  expires_at timestamptz NOT NULL,
  revoked_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_sessions_user ON sessions(user_id);

CREATE TABLE contents (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  type         text NOT NULL CHECK (type IN
               ('school','academics','outcomes','campus','student_union','news','admissions','contact')),
  category     varchar(40) NOT NULL,
  title        varchar(120) NOT NULL CHECK (char_length(btrim(title)) BETWEEN 1 AND 120),
  summary      varchar(300),
  body         text NOT NULL DEFAULT '',
  status       text NOT NULL DEFAULT 'draft'
               CHECK (status IN ('draft','pending_review','approved','published')),
  version      integer NOT NULL DEFAULT 1 CHECK (version >= 1),
  author_id    uuid NOT NULL REFERENCES users(id),
  reviewer_id  uuid REFERENCES users(id),
  published_at timestamptz,
  is_demo      boolean NOT NULL DEFAULT true,
  created_at   timestamptz NOT NULL DEFAULT now(),
  updated_at   timestamptz NOT NULL DEFAULT now(),
               CHECK (status <> 'published' OR published_at IS NOT NULL),
               CHECK (summary IS NULL OR char_length(summary) <= 300),
               CHECK (char_length(body) <= 20000),
               CHECK ((type, category) IN (            -- 25 项映射 + 学生会，见第 8 节
                 ('school','overview'),('school','head_message'),('school','mission'),
                 ('school','history'),('school','faculty'),('school','partnerships'),
                 ('academics','overview'),('academics','foundation'),('academics','ap'),
                 ('academics','alevel'),('academics','subjects'),('academics','calendar'),
                 ('outcomes','counseling'),('outcomes','outcomes'),
                 ('admissions','why_us'),('admissions','application'),('admissions','requirements'),
                 ('admissions','fees'),('admissions','faq'),('admissions','consultation'),
                 ('campus','clubs'),('campus','boarding'),('campus','facilities'),
                 ('news','updates'),('contact','contact'),('student_union','overview')
               ))
);
CREATE INDEX idx_contents_public ON contents(type, status, published_at DESC);
CREATE INDEX idx_contents_author ON contents(author_id, status);
CREATE INDEX idx_contents_news   ON contents(status, published_at DESC, id DESC);

CREATE TABLE content_revisions (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  content_id uuid NOT NULL REFERENCES contents(id) ON DELETE CASCADE,
  version    integer NOT NULL,
  snapshot   jsonb NOT NULL,
  actor_id   uuid NOT NULL REFERENCES users(id),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (content_id, version)
);
CREATE INDEX idx_revisions_content ON content_revisions(content_id, version DESC);

CREATE TABLE audit_events (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  actor_id    uuid REFERENCES users(id),               -- 可空：匿名/登录失败场景
  action      text NOT NULL,                           -- 见 6.2 审计动作注册表
  target_type text NOT NULL,
  target_id   text,
  request_id  text NOT NULL,
  result      text NOT NULL CHECK (result IN ('success','failure','denied')),
  created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_created ON audit_events(created_at DESC);
CREATE INDEX idx_audit_target  ON audit_events(target_type, target_id);
-- 只允许追加：应用数据库账号回收 UPDATE/DELETE 权限

CREATE TABLE inquiries (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  kind         text NOT NULL CHECK (kind IN ('consultation','visit')),
  test_name    varchar(40)  NOT NULL CHECK (char_length(btrim(test_name)) BETWEEN 1 AND 40),
  test_contact varchar(100) NOT NULL,
  message      varchar(500),
  status       text NOT NULL DEFAULT 'new' CHECK (status IN ('new','viewed')),  -- v1 最小值；扩展须改契约
  is_test      boolean NOT NULL DEFAULT true CHECK (is_test),
  created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_inquiries_created ON inquiries(created_at DESC);

CREATE TABLE idempotency_keys (
  scope        text NOT NULL,
  key          uuid NOT NULL,
  request_hash text NOT NULL,
  result_ref   uuid,
  expires_at   timestamptz NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (scope, key)
);
```

## 5. 审核状态机

```text
draft ──submit──> pending_review ──approve──> approved ──publish──> published
                      └──reject──> draft                 published ──unpublish──> draft
```

只有草稿作者或管理员可改草稿；送审需 title/body 满足约束；审核者不是提交者；驳回原因必填；所有转换按状态、角色和资源版本校验。每个变更在同一数据库事务中更新状态、版本并写审计/修订，冲突返回 409，任何失败不能半提交。发布已有版本可以采用 snapshot 或先下架后重编；第 1 天确定并写入 OpenAPI。不得在公开端提前看到未发布版本。管理员修改、发布和下架同样审计。

**失败码（v2）**：非法跳转 409 `INVALID_TRANSITION`；version 不匹配 409 `VERSION_CONFLICT`（details 回传服务端当前 version）；审核者即作者（含多角色账号）403 `SELF_REVIEW_FORBIDDEN`；送审字段不满足 400 `VALIDATION_FAILED`。完整错误码注册表见 6.1。

## 6. API v1 最低契约

API 使用 JSON、UTF-8；分页 `page` 默认 1、`pageSize` 默认 20 且最大 100，稳定排序 `publishedAt desc, id desc`；查询参数需校验。统一响应：成功 `{data, meta?: {page,pageSize,total}, requestId}`；失败 `{error:{code,message,details?}, requestId}`，不返回 SQL、栈或内部配置。`requestId` 可关联日志。空列表为 200 和 `[]`；无内容为 404；字段错误 400；未认证 401；无权 403；状态/版本/幂等冲突 409；限流 429；意外异常 500。日志不包含敏感请求体。

| 方法 | 路径 | 授权 / 主要行为 |
| --- | --- | --- |
| GET | `/v1/public/contents?type=&category=&page=&pageSize=` | 匿名；仅 published 的安全展示字段 |
| GET | `/v1/public/contents/{id}` | 匿名；仅 published，其他一律 404 |
| POST | `/v1/public/test-inquiries` | 仅 local/staging 且显式启用；测试标识、字段校验、限流、Idempotency-Key；生产始终关闭，禁止真实数据 |
| POST | `/v1/admin/sessions` | 登录；失败统一响应、限流；会话设置及 CSRF 策略见安全文档 |
| GET | `/v1/admin/me` | 已登录；返回账号、角色及当前环境，不含密码/令牌 |
| DELETE | `/v1/admin/sessions/current` | 已登录；服务端撤销会话并清理客户端状态 |
| GET/POST | `/v1/admin/contents` | 依权限列表/创建草稿；列表仅返回有权内容 |
| GET/PATCH | `/v1/admin/contents/{id}` | 权限校验；PATCH 带 `version`，冲突 409；限制可改字段 |
| GET | `/v1/admin/contents/{id}/revisions` | 编辑/审核/管理员按矩阵可查看的内容修订，分页；仅返回其有权查看的内容 |
| POST | `/v1/admin/contents/{id}/submit` | 作者送审；请求 version |
| POST | `/v1/admin/contents/{id}/approve` | 非作者审核通过；请求 version |
| POST | `/v1/admin/contents/{id}/reject` | 非作者驳回；version、reason 必填 |
| POST | `/v1/admin/contents/{id}/publish` | 审核人或管理员；version 必填 |
| POST | `/v1/admin/contents/{id}/unpublish` | 审核人或管理员；version 必填 |
| GET | `/v1/admin/inquiries`、`/v1/admin/inquiries/{id}` | 招办/管理员；仅测试环境合成记录 |
| GET | `/v1/admin/audit-events` | 管理员；分页、时间及动作筛选，不含敏感正文 |
| GET | `/health/live`、`/health/ready` | 探针；只返回最小状态，不泄露配置；ready 检查必要依赖 |

`Idempotency-Key` 是客户端生成的随机 UUID；同一 key 与相同请求重试返回首次结果或等价结果；同 key 不同请求 409。服务端持久化并以事务/唯一约束处理并发；明确过期时间和故障时行为。重放命中时响应加 `Idempotent-Replay: true` 头，客户端可提示"已重复提交，返回首次结果"。小程序请求失败时允许用户重试，不能把网络错误显示成成功。

### 6.1 错误码注册表（v2 收编；B/C 错误界面按 code 分派，禁止按 message 文案匹配）

| code | HTTP | 触发条件 | 客户端处理建议 |
| --- | --- | --- | --- |
| VALIDATION_FAILED | 400 | 字段缺失/类型/长度/枚举/未知字段/参数越界/请求体超限 | 表单逐字段回显 details；其余提示参数错误 |
| UNAUTHENTICATED | 401 | 无会话、会话过期/撤销/用户停用后调用受保护端点 | 清会话 → 跳登录 |
| AUTH_FAILED | 401 | 仅登录端点：用户不存在或密码错误（统一响应与耗时） | "用户名或密码错误" |
| FORBIDDEN | 403 | 已认证但角色/对象归属不满足 | 无权限提示，保留数据 |
| SELF_REVIEW_FORBIDDEN | 403 | 审核者是内容作者（含多角色账号） | "不能审核自己提交的内容" |
| CSRF_INVALID | 403 | 写请求 CSRF token 缺失或不匹配 | 引导重新登录后重试 |
| NOT_FOUND | 404 | 资源不存在；匿名端对未发布内容一律 404（本仓库统一策略） | "内容不存在或已下架" |
| VERSION_CONFLICT | 409 | 乐观锁 version 不匹配 | 冲突对话框，回传服务端当前 version |
| INVALID_TRANSITION | 409 | 状态机非法跳转 | 刷新详情并解释当前状态 |
| IDEMPOTENCY_CONFLICT | 409 | 同 Idempotency-Key 不同请求哈希 | 提示刷新/重新提交 |
| RATE_LIMITED | 429 | 超过端点限流 | "操作太频繁，请稍后再试" |
| INTERNAL_ERROR | 500 | 未捕获异常（响应含 requestId，不含细节） | "服务异常" + requestId |

## 7. 联调用例与确定性字段

这些值用于启动联调，A 应将其写入 OpenAPI 及数据库约束；若需要变化由三人共同确认并同步例子。

- `title` 去除首尾空白后 1–120 字符；`summary` 0–300；`body` 1–20,000；`reason` 去空白后 1–500；超限返回 400；空正文可保存草稿但不可送审。拒绝未知字段。
- 测试咨询请求 `{"kind":"consultation","testName":"测试姓名","testContact":"test@example.invalid","message":"虚构测试","isTest":true}`。`kind` 可为 `consultation` 或 `visit`，`testName` 1–40、`testContact` 1–100、`message` 0–500 字符；必须标记测试，后台清楚表明不是正式联系方式。`Idempotency-Key` 为 UUID，请求头携带；默认保留 24 小时，scope 按测试环境+端点，真实时长在部署文档标明。请求 hash 用经验证字段规范化后的完整内容计算。
- 登录请求以 `username`、`password` 为输入；成功响应不包含密码或 cookie 值；当前用户响应包含 `id`、`username`、`roles`、`environment`。浏览器请求和 CSRF 处理方式由 A 在第 1 天约定并提供示例。
- 创建草稿传 `type`、`category`、`title`、`summary`、`body`、`isDemo`；服务端自行设置 `authorId`、`status=draft`、`version=1`，返回 `id` 和 `version`。状态切换请求传当前 `version`；驳回另外带 `reason`。服务端生成角色、审计时间、审核者和发布时间，不能由客户端指定。
- 客户端收到 `409` 时保留输入并提示刷新或重试；从列表进入详情、修改和删除浏览器缓存时均遵循服务端资源状态，禁止把草稿响应复用到匿名页面。

## 9. 并行交付中的契约

- A 在第 1 天提交 OpenAPI、3 个完整 request/response、种子和状态约束；第 2 天上线可调用测试接口；变更要更新契约与双方 PR。
- B 实现客户端封装、类型、超时、错误/空态、测试咨询调用；不能携带后台凭据。
- C 实现有认证的 API 客户端、表单防重复、状态机按钮和 401/403/409 展示；不通过前端自行决定权限。
- 三人第 3 天以合成数据联测：匿名看不到草稿；editor 送审；reviewer 审核发布；匿名可以看到；测试咨询记录仅 admissions/admin 可读。
