# 部署、回滚与备份恢复

## 发布前

1. 固定 commit、镜像 tag 和锁文件。
2. `AUTO_MIGRATE` 默认关闭，部署脚本必须先显式执行 `pnpm migrate`；只有本地 Compose 默认启用自动迁移。
3. 校验 `NODE_ENV`、数据库 URL、精确 CORS、会话 secret、咨询开关。
4. 先备份，再执行前向迁移，再启动 API。
5. 验证 `/health/live` 与 `/health/ready`。
6. 不把密钥写入镜像层、仓库或日志。

## 回滚

1. 记录当前镜像 tag、数据库 schema 版本、失败现象。
2. 回退 API 镜像/配置到旧 tag。
3. 若数据库只做前向兼容变更，可直接回退代码；若迁移破坏兼容，禁止只回退代码，按恢复方案处理并明确数据丢失范围。
4. 回退后验证 health、登录、匿名内容列表和一次内容状态动作。
5. 记录开始/结束时间、操作者、版本和结果。

## 备份恢复演练

```bash
NODE_ENV=staging \
SOURCE_DATABASE_URL='postgresql://.../cfls_test' \
TARGET_DATABASE_URL='postgresql://.../cfls_restore' \
infra/scripts/backup-restore.sh
```

脚本拒绝相同源/目标数据库与生产环境。恢复目标必须是独立临时库，不得覆盖源库。核对表结构、用户数、内容数、咨询数和内容状态。
