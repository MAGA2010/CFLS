# 测试、质量门禁与验收记录

## 执行规则

每条用例记录 ID、被测 commit、环境/浏览器/微信工具版本、测试人、前置条件、步骤、预期、实际、通过/失败/阻塞、截图或日志链接、缺陷和复测人。自动化测试要保存命令及 CI 链接。未执行、依赖缺失或只有截图没有可复现步骤均不可计为通过。P0 全通过才接受阶段成果；生产另验收。

## C. 身份、安全和数据

| ID | 前置及步骤 | 可观察预期 | 级别 |
| --- | --- | --- | --- |
| S01 | 无会话调用任意管理 API；用过期/注销会话重试 | 返回 401，无受保护数据 | P0 |
| S02 | 分别用 editor、reviewer、admissions、admin 逐项调用权限矩阵；绕过页面直接请求 | 每个越权操作被服务端拒绝且未修改数据；非授权角色读不到咨询 | P0 |
| S03 | 多角色作者尝试审核本人内容；对不允许的状态强制调用发布/审核 | 服务端拒绝，状态不变，审计可查 | P0 |
| S04 | 登录失败、暴力重复请求、无效数据、过长字段、脚本片段、SQL 特殊字符 | 限流和校验生效，无脚本执行、注入、敏感错误或数据库污染 | P0 |
| S05 | 测试跨站写请求/CSRF；登出后访问；检查 cookie 属性（HTTPS 测试环境） | 跨站写被拒、注销后不可用；属性与设计一致；无令牌泄漏 | P0 |
| S06 | `local/staging` 显式开启测试咨询；提交虚构信息，重复同 key，同 key 改内容；切到生产配置测试 | 相同请求仅一条记录/等价响应；不同请求 409；生产提交关闭；日志不含正文 | P0 |
| S07 | 用 admin 查审计，普通角色尝试读取；检查日志 | 授权可查并有 actor/action/result/requestId，无授权不能读取，日志不含凭据和个人内容 | P0 |
| S08 | 根据项目约定检查依赖漏洞、环境变量和权限 | 高严重度问题处理或记录明确责任与阻塞；敏感配置未提交 | P0 |

## 缺陷分级和关闭

阻断：无法启动/部署、越权、数据暴露、状态错乱、数据丢失、主链路不可用；未修复不得通过 P0。高：核心模块明显不可用或严重错误；项目负责人决定是否影响 P0，但不能掩盖。中/低：可绕过或视觉问题，列入遗留并注明责任人与期限。每个缺陷要有可复现步骤、环境、影响、负责人、修复 commit 和独立复测结果。
