# 七天范围、排期和阶段验收

## 1. 交付范围

**P0 必须完成**：可构建的小程序、可构建 Web 后台、API 和 PostgreSQL 的单仓库；本地一键启动 API/数据库及迁移/种子；学校、课程、升学、校园、学生会、新闻、招生/联系七类内容及 25 项需求映射；新闻列表/详情；角色隔离；草稿→送审→审核→发布及下架；匿名端仅见已发布内容；测试环境的虚构咨询提交与招办查看；服务端校验及必要安全控制；自动化测试、CI、部署/回滚/恢复演练和交付文档。

**P1 争取完成**：课程/新闻筛选搜索、活动列表和报名测试流程、校历列表、后台素材上传、细粒度栏目权限、操作台统计、移动端真机/体验版、独立测试环境 HTTPS 和告警联调。功能未完成则显示清楚的待完成状态，列入缺陷；不能将未实现的功能假装成功。

**生产前单独验收**：学校主体和小程序/域名资质、学校正式内容及素材授权、隐私告知与个人信息处理方案、真实招生表单与处理责任、生产环境/密钥/监控/备份与恢复、渗透和安全评估、容量测试、可用性演练、平台审核、校方审批。具体依法和校方要求办理；本计划不替代法律或安全审查。官网 Web 独立前台、微信登录/订阅消息、支付、复杂升学数据库/图表为后续范围。

**25 项栏目**：每项必须映射到可访问页面/区块、后台内容类型及状态；经确认的内容可在测试环境展示，缺失内容使用“待学校确认”占位。映射不等于 25 项都达到生产功能深度。所有演示数据标记合成数据。

## 2. 每日交付与决策门

| 日 | A 后端/平台 | B 小程序 | C 后台 | 门禁与负责人检查 |
| --- | --- | --- | --- | --- |
| 1 | 建单仓库、API/DB 骨架、运行与契约、角色和状态机 | 小程序工程/路由/页面骨架，验证微信工具链 | 后台工程、登录页/布局与接口 mock | 三人可启动；冻结 OpenAPI v1、模型、测试账号方案；列出缺口 |
| 2 | 认证、RBAC、内容表和列表详情 API、迁移与种子 | 首页、导航、学校/课程页接 API | 登录、内容列表/新建/编辑接 API | 登录、匿名列表和一个内容详情贯通；接口评审 |
| 3 | 送审/审核/发布 API、审计和并发版本校验 | 升学、校园、新闻列表详情 | 送审、审核、发布、历史与权限提示 | 编辑→审核→发布→小程序可见，匿名不可见草稿 |
| 4 | 咨询 API、校验/限流/幂等、错误处理、CI | 招生、联系、合成咨询表单和异常状态 | 招办咨询列表/详情、审计列表 | 用合成数据完整走通并验证越权与重复提交 |
| 5 | 补测试、容器化、备份/恢复与部署流程 | 栏目映射补齐、空/异常/适配、单测 | 管理交互和权限测试、栏目映射补齐 | 全部 P0 合并；检查风险与缺陷，冻结功能 |
| 6 | 自动化、性能基线、恢复演练、修阻塞 | 微信工具测试、回归、修阻塞 | 后台跨浏览器与越权回归、修阻塞 | 按独立验收表执行，列出每项证据和责任人 |
| 7 | 干净环境复现、版本标识、最终运行/运维交付 | 最终 commit 回归与小程序证据 | 最终 commit 回归、操作手册/录屏 | 在固定版本验收，记录通过/失败/阻塞；负责人决定是否接受 |

七天按实际启动日和团队投入计算，不默认为七个自然日。任务量大，第 1 天资源和工具门禁失败时须立即调整日期或 P1；不能将关键安全和审查任务省略后继续称为达标。

## 3. 交付物

1. main 上固定 commit、各 PR 与至少一人 review；完整源码、依赖锁文件、OpenAPI、迁移及可重复种子。
2. README 含系统要求、安装/构建/运行/测试、数据库初始化、微信导入、后台测试账号生成方式、常见问题、环境隔离、服务地址及限制。
3. `docs/` 含 25 项映射、架构图/数据模型、API 契约、权限矩阵、运维及备份恢复记录、测试与缺陷清单、上线前清单和交接人。
4. 自动化检查结果、API 测试、角色矩阵/越权测试、编辑发布端到端记录、设备适配记录、备份恢复演练报告、2–3 分钟演示录屏。
5. 明确列出：已实现、仅测试环境可用、未实现、上线阻塞、风险责任人和截止时间。

## 4. 项目负责人验收

按 [测试与验收用例](测试与验收用例.md) 操作，每条填写版本、环境、操作人、结果与证据。P0 只有全部通过才叫阶段验收通过；任何未测、无证据或失败都不能标通过。P1 遗留由负责人记录并决定是否接受候选版。上线门槛未完成时不得部署公开生产服务或采集真实信息。
